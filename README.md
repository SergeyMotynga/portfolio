# Портфолио Сергея Мотынги

Статический сайт на Astro и TypeScript: Python backend, командные проекты и ML-практика. Русская версия находится на `/ru/`, английская — на `/en/`. Корень перенаправляет на русскую версию.

## Локальный запуск

Нужен Node.js 24.

```powershell
npm ci
npm run dev
```

Адрес по умолчанию: `http://127.0.0.1:4321/`.

```powershell
npm run verify
npm run preview
```

`verify` проверяет Astro/TypeScript, собирает сайт и проверяет готовые страницы. `preview` показывает production-сборку. В ограниченном окружении можно отключить телеметрию перед командами: `$env:ASTRO_TELEMETRY_DISABLED = '1'`.

## Как добавить проект

1. Создать папку `src/content/projects/<key>/`. Ключ — латинские буквы в нижнем регистре, цифры и дефисы.
2. Добавить `ru.md` и `en.md` с одинаковым `key`. Взять структуру полей у существующего проекта.
3. Заполнить `title`, `summary`, `contribution`, `stack`, `category`, `disclosure` и Markdown-текст. `contribution` используется и в раскрываемом описании, и на странице кейса.
4. Через `order` выбрать положение в списке; `featured: true` выводит работу в избранные. Для ограниченных материалов избранное запрещено схемой.
5. Выполнить `npm run verify` и отправить изменения в рабочей ветке через PR.

Схема проверяет обязательные поля и политику ссылок. Сборка останавливается при пропущенном переводе или повторе пары `key`/`lang`. Страницы кейсов создаются автоматически, отдельные маршруты добавлять не нужно.

## Что где менять

| Что | Источник |
|---|---|
| Тексты и сведения о проекте | `src/content/projects/<key>/<lang>.md` |
| GitHub, почта, Telegram; будущий PDF | `src/data/profile.ts` |
| Хакатоны и выступления | `presentations` в `src/data/profile.ts` |
| Подписи интерфейса | `src/i18n/ui.ts` |
| Оформление | `src/styles/global.css` |
| Разрешённые ссылки на репозитории | `src/lib/publication-policy.ts` |
| Требования и ограничения контента | [docs/portfolio-spec.md](docs/portfolio-spec.md) |

Поля `email`, `telegram` и `resume` необязательные. Пока они отсутствуют, сайт их не показывает. Для резюме нужно положить согласованные PDF в `public/` и указать пути в `profile.resume.ru` и `profile.resume.en`.

Коммерческие и корпоративные кейсы обезличены. Внутренние адреса, исходники, материалы заказчиков, закрытые данные и неподтверждённые показатели в этот репозиторий не переносить. Добавление внешней ссылки требует согласования и изменения поддерживаемого списка разрешённых URL.

## Размещение на Cloudflare Pages

Сайт собирается в обычный каталог `dist/`; серверный адаптер и база данных не нужны.

| Настройка | Значение |
|---|---|
| Repository | Этот репозиторий |
| Production branch | `main`, после принятия изменений |
| Build command | `npm run verify` |
| Build output directory | `dist` |
| Node version | `24` (также указан в `.node-version`) |
| `SITE_URL` | Полный HTTPS-адрес опубликованного сайта, без выдуманного домена |

`SITE_URL` задаётся переменной окружения сборки и включает абсолютные canonical/og:url. Пока адрес не известен, эти метаданные не создаются. `public/_headers` задаёт заголовки для статической выдачи Cloudflare Pages. До подключения GitHub к Cloudflare и запуска deployment сайт остаётся локальным; наличие этого раздела не означает публикацию.

## Проверки

CI выполняет `npm run verify` в Node.js 24. Проверяются схема и отрицательные сценарии публикации, полнота RU/EN, маршруты, внутренние якоря, переход между переводами кейса, публичные ссылки и отсутствие внутренних идентификаторов в готовом сайте.

Приложение отдаёт содержимое в статическом HTML. Меню, раскрываемый каталог и переходы работают без клиентского JavaScript. Глобальный фонарик следует за курсором во всех разделах. Навигация остаётся закреплённой, её фон занимает всю ширину окна. Модуль `src/scripts/motion.ts` добавляет появление строк имени, уход всего первого экрана при прокрутке, последовательное появление слов заголовков и разные направления движения блоков. Вместо схемы первого экрана используется 3D-бейдж с котиком. Появления блоков обратимы при прокрутке, меню ведёт прямо к секциям. Автоматическая анимация бейджа и фона короткая, без бесконечных циклов. Эффекты учитывают `prefers-reduced-motion`; тяжёлого клиентского фреймворка нет.

## Работа с интерфейсом

Проектный frontend-harness подключён в [AGENTS.md](AGENTS.md): десять скиллов frontend-профиля, `design-taste-frontend` и восемь UI-скиллов Jakub Krehel. Полные ресурсы находятся в `.agents/skills/`, точные версии источников и условия применения — в инструкциях. Эти файлы используются агентом и не входят в `dist/`.

Перед изменением UI читай [карту компонентов и движения](docs/design-system.md). Сначала переиспользуй существующие Astro-компоненты и CSS-токены. Правки текстов проектов обсуждаются отдельно от оформления.

## Визуальные компоненты

Основной рабочий клон владельца: `C:\Users\motyn\Desktop\repositories\portfolio`. Изменения вносятся непосредственно в него; локальный dev-сервер обновляет их без промежуточного push/pull.

Палитра — лаванда #BFA7FF и графит #111018. Фон — MoltenMetal, за разделом «Обо мне» расположен крупный CrystalizedBall. Четыре компактные карточки помещаются в ряд на широком экране. Проекты — карточки с переворотом и бликом; справа на первом экране — Lanyard с временной иллюстрацией котика. WebGL-модули подгружаются отдельно, React не используется. Статичные изображения и текст доступны без JavaScript, 3D отключено при reduced motion. См. [источники и лицензии](docs/third-party.md).

Шрифты поставляются локально: Tanker/Bespoke Serif для латиницы, Oswald/PT Serif для кириллицы. Отдельных круглых кнопок переворота нет; проект раскрывается нажатием карточки, клавиатурные действия сохраняются.
