# Первая версия портфолио

Источник требований — согласованные решения владельца. Учёт реализации: [Issue #1](https://github.com/SergeyMotynga/portfolio/issues/1). Эта страница хранит продуктовые решения; содержимое проектов поддерживается в Markdown, без копии текста кейсов здесь.

## Аудитория и позиционирование

Портфолио для работодателей. Основное направление — Python backend, дополнительное — ML Engineering. Целевые вакансии: Junior+ / начинающий Middle. Уровень владения английским не выводится из наличия английской версии сайта.

## Страницы и структура

- Полные русская и английская версии. Переключение языка сохраняет текущий кейс.
- Главная: краткое представление, избранные проекты и раскрываемый каталог остальных, хакатоны/выступления, стек/образование, контакты.
- Отдельного раздела опыта работы нет. Коммерческий вклад представлен среди проектов.
- Подробные страницы кейсов генерируются из Markdown. Один проект — папка с двумя переводами, единый ключ и общая схема.
- Нет блогов, аккаунтов, формы обратной связи, аналитики и обязательной загрузочной заставки.

## Визуальное направление

Выбран вариант «Структура»: тёмный фон, крупная типографика, тёплый оранжевый акцент, тонкие линии и строки проектов. Дополнительно владелец выбрал выразительное движение: реакцию на курсор, прокрутку и интерактивные элементы. Содержимое видно сразу. Вёрстка адаптируется к мобильному экрану, навигация доступна с клавиатуры. Не нужна тяжёлая 3D-сцена.

На первом экране — демонстрационная схема пути запроса с выбором API/данные/ML, движением потока и реакцией на курсор. Она не отправляет реальные API-запросы и не показывает выдуманные показатели. Есть пауза; при `prefers-reduced-motion` движение отключено. Появление секций при прокрутке и раскрытие проектов анимируются с прогрессивным улучшением: без JavaScript содержимое и навигация остаются доступны.

После просмотра на широком экране согласовано: страница занимает доступную ширину с адаптивными полями, имя и фамилия становятся главным крупным заголовком, специализация — подзаголовком. Свечение и сетка располагаются на общем фоне без прямоугольных границ секции. Схема показывает последовательный маршрут запроса; этап данных заменяется ML при выборе соответствующего сценария. Описания проектов на этом этапе не меняются.

Движение текста: строки имени появляются при первом открытии, затем при начале прокрутки имя уходит вверх и растворяется. Заголовки следующих секций раскрываются по словам, строки проектов и блоки появляются с разными направлениями и короткой последовательной задержкой. Фон дополняется сеткой и мягкими орбитами. Прокрутка нативная, без удержания пользователя на заставке. Кнопка паузы схемы останавливает также фон и текстовые эффекты; reduced motion показывает статическое содержимое, а клавиатурный фокус восстанавливает читаемость уходящего блока.

## Контент и публикация

- Согласованы 12 логических проектов. Четыре избранных: система работы с аудиобейджами, система контроля дефектов, корпоративный Git-синхронизатор и Daily Organizer.
- Дополнительные: SPAS System, AutomationML, учебный RAG, Time Series Task, FinGuru, шахматная трансляция, Royality и обезличенный ML-кейс прогнозирования спроса.
- Daily Organizer обозначается как пет-проект, RAG — как учебный.
- Коммерческие проекты показываются под обезличенными названиями. Внутренние имена репозиториев, заказчики и корпоративные адреса в выдаваемых страницах отсутствуют.
- Внешние ссылки допустимы только на согласованные личные открытые GitHub-работы. Поддерживаемый список находится в `src/lib/publication-policy.ts`, схема — в `src/lib/project-schema.ts`.
- Ограниченный ML-кейс — только общий обзор подхода. Данные, код, ноутбуки, предсказания, презентации, графики, точные результаты и идентификаторы организатора не публикуются. Полные дополнительные условия лицензии пока не получены; это не разрешение на публикацию материалов.
- Командные результаты не выдаются за единоличный вклад. Количественные достижения, production-статус и прохождение чужого CI не заявляются без подтверждения.
- FinGuru представлялся на хакатоне; SPAS — на конференции по приглашению. Названия мероприятий, даты и награды добавляются только после подтверждения владельцем.

## Отложенное наполнение

Прямые контакты, PDF-резюме и дипломы владелец предоставит позже. Пока они не добавлены, отсутствуют соответствующие действия и неподтверждённые даты/результаты. Личный GitHub используется как доступный контакт.

## Техническая основа и границы этапа

Astro, TypeScript, статическая сборка, CSS и небольшой клиентский модуль анимации без UI-фреймворка. Сервер, CMS и база данных для первой версии не требуются. Чтение страниц, каталог, навигация и выбор языка работают без JavaScript; интерактивная схема и дополнительные эффекты подключаются в браузере.

Текущий этап — рабочий сайт в репозитории, проверки и draft PR. Публичное размещение на Cloudflare Pages и домен — отдельный этап. Мерж и перевод PR в ready автоматически не выполняются.
